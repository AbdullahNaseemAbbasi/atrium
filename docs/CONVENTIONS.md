# Atrium engineering conventions

Read this before adding a page, query or action. The goal is that every
screen looks and behaves like the ones already built.

## Stack facts (Next.js 16.4, React 19.3, Tailwind 4)

- **Cache Components + Partial Prefetching are on.** Request data
  (`params`, `searchParams`, `cookies()`) must be read **inside a
  `<Suspense>` boundary**. Page components therefore stay synchronous and
  pass the promises into an async child rendered inside `<Suspense>`:

  ```tsx
  export default function Page({ params, searchParams }: PageProps<"/w/[org]/clients">) {
    return (
      <Suspense fallback={<Skeleton className="h-96 rounded-2xl" />}>
        <Clients params={params} searchParams={searchParams} />
      </Suspense>
    );
  }
  async function Clients({ params, searchParams }: { params: Promise<{ org: string }>; searchParams: Promise<Record<string, string | string[] | undefined>> }) {
    const [{ org }, query] = await Promise.all([params, searchParams]);
    const data = await listClients(org, { q: firstParam(query.q) });
    …
  }
  ```

  `PageProps<"/route">` and `LayoutProps<"/route">` are global types
  (generated by `next typegen`; `pnpm typecheck` runs it).
- Client components that call `useSearchParams`, `usePathname`, `useParams`
  must also render inside a `<Suspense>` boundary (they are, if they live in
  the async child above).
- `getCurrentUser()` calls `connection()`, so after any `require*Context()`
  call it's safe to read the clock (`new Date()`). Never call `new Date()`
  in a component before the context is resolved.
- **Do not wrap loaders in React `cache()`**: sharing one promise between a
  layout and its page breaks instant-navigation validation.
- New top-level authenticated layouts (`/portal/[org]`, `/admin`) export
  `export const instant = false;` like `app/w/[org]/layout.tsx`.
- `middleware` is now `proxy.ts` (already set up). Mutations use server
  actions; after a mutation call `refresh()` (from `next/cache`) or
  `revalidatePath`, or `redirect()`.
- lucide-react 1.x has no brand icons (no `Github`, `Slack`, `Figma`). Use a
  `BrandTile` (letters) instead.
- Lint (React 19 rules): **never call `setState` synchronously inside
  `useEffect`.** Close dialogs from the action wrapper or event handler
  instead (see `NewVersionButton` in `components/deliverables/deliverable-actions.tsx`).
  Escape apostrophes in JSX text (`&apos;`).

## Layers

| Layer | Location | Rules |
|---|---|---|
| Types | `lib/data/types.ts` | Domain model. Every tenant row has `organizationId`. |
| Demo data | `lib/data/seed.ts`, `lib/data/store.ts` | In-memory DB (`getDb()`), replaced by Supabase later. |
| Access rules | `lib/data/access.ts` | Pure functions: `resolveTeamContext`, `canViewProject`, `visibleProjects`, `canViewDeliverable`, `visibleComments`, `canDecideOnDeliverable`… |
| Permissions | `lib/auth/permissions.ts` | `can(role, "clients.manage")`, `clientCan(role, "portal.approve")`, role labels. |
| Auth/DAL | `lib/auth/context.ts` | `requireTeamContext(orgSlug)`, `requireClientContext(orgSlug)`, `requirePlatformAdmin()`, `getCurrentUser()`. |
| Read models | `lib/data/views.ts` | `summarizeProject`, `toTaskRow`, `toDeliverableRow`, `toCommentView`, `toActivityView`, `paginate`, `newestFirst`, `userLite`, `clientLite`, `taskDueText`. |
| Business rules | `lib/domain/rules.ts`, `lib/domain/metrics.ts` | Progress, overdue, milestone blockers, deliverable state machine, KPI formulas. |
| Labels | `lib/domain/labels.ts` | Status/priority labels + tones. |
| Queries | `lib/data/queries/<area>.ts` | `import "server-only"`. Start with `require*Context`, return plain serialisable objects (ISO strings, no functions, no class instances). |
| Actions | `lib/actions/<area>.ts` | `"use server"` file; only async exports. Re-check auth + permission + tenant ownership of every referenced id; validate with zod (`lib/validation/schemas.ts` or a local schema); write audit/activity/notifications via `lib/data/events.ts`; return `ActionState` (`ok`, `fail`, `invalid` from `lib/actions/result.ts`). |
| Billing catalogue | `lib/billing/plans.ts` | `PLANS`, `getPlan`, `checkLimit`. Limits are enforced in actions. |

### Security rules (non-negotiable)

1. Never trust an id from the client. Load the row, check
   `row.organizationId === ctx.org.id`, then the resource rule
   (`getVisibleProject`, `canViewDeliverable`…).
2. Out-of-tenant or invisible resources render **404** (`notFound()`), never
   403, so ids can't be probed.
3. Client users only ever see: shared projects of their own client,
   `clientVisible` tasks, non-draft deliverables, `visibility: "client"`
   comments/files/activity. Internal notes and budgets never reach them.
4. Billing managers see billing only (no project data).
5. Every security-relevant change writes `recordAudit(...)`.

## UI kit (`components/ui`)

- `card.tsx`: `Card`, `CardHeader({icon,title,description,action})`, `CardBody`, `IconBox`, `Divider`.
- `button.tsx`: `Button` (variants `primary | secondary | outline | ghost | danger | link`, sizes `xs sm md lg icon icon-sm`, `asChild`), `buttonClasses()` for `<Link>`.
- `badge.tsx`: `Badge({tone})` + status badges (project, task, deliverable, milestone, priority, client, invoice, subscription, invitation).
- `form.tsx`: `Field`, `Input`, `Textarea`, `Select`, `Checkbox`, `Label`, `FormMessage`.
- `interactive.tsx` (client): `SubmitButton`, `SearchInput` (writes `?q=`), `ParamSelect`, `Switch`, `ConfirmSubmit`.
- `misc.tsx`: `PageHeader`, `Breadcrumbs`, `EmptyState`, `Skeleton`, `TableSkeleton`, `CardSkeleton`, `StatGridSkeleton`, `TableWrap/Table/THead/Th/Tr/Td`, `FilterChips`, `Pagination`, `ProgressBar`, `DetailList`, `FormNote`, `Kbd`.
- `dialog.tsx`, `dropdown.tsx`, `nav-tabs.tsx` (route tabs), `row-actions.tsx`, `stat-card.tsx`, `sparkline.tsx`, `flash-toast.tsx`, `avatar.tsx` (`Avatar`, `AvatarStack`, `BrandTile`).
- Feature components to reuse: `components/comments/comment-thread.tsx`,
  `components/files/{file-picker,file-type-icon,file-preview,download-button}.tsx`,
  `components/tasks/*`, `components/projects/{project-form,project-icon}.tsx`,
  `components/deliverables/deliverable-actions.tsx`, `components/shell/*`.
- Toasts: `import { toast } from "sonner"`.

## Visual language

Match `app/w/[org]/page.tsx` (dashboard) and the project pages:
deep navy canvas, `card` glass panels, cyan accent (`text-cyan-300`,
`bg-cyan-500/10`), `text-ink / ink-secondary / ink-muted / ink-faint` for
text, glowing active states, tables with `THead`/`Tr`. Page = `PageHeader`
+ cards. Every list has a loading skeleton, an empty state with a next step,
and every form shows inline field errors. Copy is short, specific and
human (no "Unlock the power of…", no emoji). Synthetic data only;
emails use the `.example` domain.

### Mobile overflow rule

Any element with `overflow-x-auto` (table scrollers, tab bars, boards) must
also be `relative`. Otherwise absolutely positioned children such as
`sr-only` labels escape the scroller and make the whole page scroll
sideways on phones. `TableWrap` already does this. Grid/flex children that
contain wide content need `min-w-0` (`Card` already has it).
